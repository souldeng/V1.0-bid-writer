# Bid-Writer

面向政企项目申报、投标和解决方案材料的章节级 AI 写作工作台。它把项目事实、目录结构、项目资料、人工编辑和 Word 导出放在同一条工作流中：用户掌握事实与目录，AI 只负责辅助起草和优化，最终内容仍由用户审核确认。

> 本仓库仅应包含源代码、脱敏示例和必要的公开文档。请勿提交真实项目资料、个人信息、导出的交付文件或任何密钥。

## 核心能力

- **项目工作台**：创建、编辑、切换和删除项目；项目名称是唯一必填项，预算、申报级别、建设领域等事实仅在用户主动填写后使用。
- **可编辑目录**：支持最多四级目录的新增、重命名、排序、层级调整和删除；目录与正文分离管理。
- **章节写作**：按当前章节生成正文或基于已有内容进行 AI 优化；支持流式输出与停止生成。
- **写作指导**：依据章节语义提供可读的推荐写作要点，帮助用户补充项目的特殊要求，而不是编写技术提示词。
- **项目资料引用**：可解析 PDF、DOCX、TXT 和 Markdown 等资料；启用“参考项目资料”后，使用当前项目内的轻量 BM25 检索为章节生成提供上下文。
- **安全编辑与保存**：生成过程绑定具体项目和章节；切换前保护未保存修改，生成失败时恢复原正文，正文可被明确删除为空白。
- **可编辑 DOCX 导出**：按完整目录结构导出 Word 文档，即使中间目录暂无正文也保留标题；支持项目级页面、正文和 H1–H4 标题样式配置。

## 使用边界

Bid-Writer 是写作辅助工具，不会替代项目负责人对事实、政策、预算或交付承诺的审核。尤其应注意：

- 空白的可选项目事实不会被系统补全为确定信息。
- 政策名称、文号、预算金额、技术能力和承诺事项需要以已确认资料为准。
- BM25 是基于词项匹配的轻量检索，不等同于语义检索或事实核验。
- AI 生成内容是可编辑初稿，导出前应结合项目材料和业务事实复核。

## 架构概览

```text
浏览器工作台
  ├─ 项目 / 目录 / 章节正文
  ├─ 项目资料 → 文本分块 → BM25 检索
  └─ Next.js API → 统一 LLM Service → Doubao Provider Adapter
                                      └─ 流式正文

项目目录决定 DOCX 的标题结构；已保存章节正文只决定标题后是否附带正文。
```

模型调用经统一的服务接口进入当前的豆包 Provider Adapter。密钥仅保存在服务端环境变量中；产品界面不提供模型选择、自动路由或多模型回退。

## 本地启动

### 前置条件

- Node.js 20 或更高版本
- 可用的模型服务配置（章节生成时需要）

### 安装与配置

```bash
npm install
```

将 [`.env.example`](./.env.example) 复制为 `.env.local`，并填写你自己的服务端配置。不要提交 `.env.local`，也不要将任何 API Key 写入示例、测试数据或文档。

当前默认支持豆包配置；同时保留统一的 `LLM_PROVIDER` / `LLM_MODEL` 配置入口。字段含义以 `.env.example` 中的说明为准。

```bash
npm run dev
```

启动后访问 `http://localhost:3000`。

## 当前范围

本项目聚焦单人使用场景下的项目写作闭环。当前不提供：

- 用户认证、多人协作、审批或专家评审；
- OCR、自动拆解需求书或自动生成最终目录；
- 向量数据库、复杂检索编排、多 Agent 或多模型路由；
- 内容版本库、复杂 Word 模板解析、图片与复杂表格排版。

## 数据与安全

- 本地开发数据、真实材料和评测结果应保留在忽略目录中，不应进入公开仓库。
- 项目资料仅应上传你有权处理的文件；含敏感信息的内容应先脱敏。
- 导出的 Word 文件位于用户本地，发布前同样需要人工检查敏感信息。
