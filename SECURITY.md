# Security Policy

## Reporting a vulnerability

Please do not include credentials, personal data, customer materials, or detailed exploit steps in a public issue.

If GitHub private vulnerability reporting is enabled for this repository, use it to send a report. If it is unavailable, open a minimal public issue requesting a private contact channel, without disclosing the vulnerability details.

Include the affected version or commit, a minimal reproduction using synthetic data, the impact you observed, and any mitigation already applied. Reports are handled on a best-effort basis; no response or remediation time is promised.

## Scope

Treat exposed API keys, uploaded-document access across projects, unintended export of stored material, and unsafe file handling as security issues. Rotate any exposed provider credential immediately rather than waiting for a response.
